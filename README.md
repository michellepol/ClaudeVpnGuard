# ClaudeVpnGuard

Утилита для Windows, которая не даёт трафику Claude уйти мимо VPN. Она ставит
постоянные фильтры Windows Filtering Platform и держит службу, которая обновляет
их при появлении и пересоздании VPN-адаптера. Когда VPN выключен, Claude Code и
сайты Claude остаются без сети, всё остальное работает как обычно.

Правило: разрешено только через адаптер `AmneziaVPN`, на всех остальных
интерфейсах запрещено:

1. любые исходящие соединения к диапазонам адресов Anthropic, от любого процесса;
2. любые исходящие соединения `claude.exe`, кроме loopback.

Фильтры постоянные: они действуют до старта службы, после её падения и после
перезагрузки. Любой сбой ведёт к блокировке, а не к утечке.

## Сборка

Нужен .NET SDK 9, только x64.

```powershell
dotnet test
dotnet publish src/ClaudeVpnGuard -c Release -r win-x64 --self-contained `
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o publish
```

В `publish` появится один `ClaudeVpnGuard.exe`.

## Использование

Все три команды лучше запускать из терминала администратора.

```powershell
.\publish\ClaudeVpnGuard.exe install     # копирует exe, создаёт конфиг, ставит фильтры и службу
.\publish\ClaudeVpnGuard.exe status      # состояние службы, фильтров, адаптера и доменов
.\publish\ClaudeVpnGuard.exe uninstall   # удаляет службу и фильтры; файлы и конфиг остаются
```

- `install` и `uninstall` без прав администратора ничего не делают и завершаются
  с кодом 1. Повторный `install` безопасен: обновляет exe и фильтры.
- `status` без прав администратора не может прочитать фильтры и поэтому всегда
  выдаёт предупреждение; полная проверка — только из терминала администратора.

Коды возврата:

| Код | Значение |
|---|---|
| 0 | всё в порядке |
| 1 | ошибка или неверная команда |
| 2 | `status` нашёл предупреждения |

### Аварийный выход

Если Claude остался без сети и разбираться некогда:

```powershell
& "C:\Program Files\ClaudeVpnGuard\ClaudeVpnGuard.exe" uninstall
```

Из терминала администратора. Служба и все фильтры удаляются, сеть работает как
до установки.

## Конфиг

`C:\Program Files\ClaudeVpnGuard\config.json`, создаётся при первом `install`:

```json
{
  "adapterName": "AmneziaVPN",
  "ipv4Cidrs": ["160.79.104.0/21"],
  "ipv6Cidrs": ["2607:6bc0::/48"],
  "appPaths": ["C:\\Users\\ME\\.local\\bin\\claude.exe"],
  "checkDomains": [
    "api.anthropic.com", "claude.ai", "claude.com",
    "platform.claude.com", "console.anthropic.com", "mcp-proxy.anthropic.com"
  ]
}
```

| Поле | Значение |
|---|---|
| `adapterName` | имя VPN-адаптера, через который трафик разрешён |
| `ipv4Cidrs`, `ipv6Cidrs` | диапазоны адресов Anthropic |
| `appPaths` | полные пути (с буквой локального диска) к приложениям, которым сеть разрешена только через VPN |
| `checkDomains` | имена, которые `status` резолвит и сверяет с диапазонами |

- Неизвестные ключи отклоняются: опечатка в имени поля — ошибка, а не тихо
  пропущенная настройка. Регистр букв в именах ключей не важен. Комментарии и
  завершающие запятые допустимы.
- После правки конфига: `Restart-Service ClaudeVpnGuard`. До перезапуска `status`
  покажет, что набор фильтров не соответствует конфигу.
- Конфиг по умолчанию берёт путь к `claude.exe` из профиля той учётной записи,
  от имени которой запущен `install`. Если терминал администратора открыт под
  другой учётной записью, путь укажет на её профиль — проверьте `appPaths`.
- Если файла из `appPaths` нет, приложение всё равно блокируется по пути из
  конфига, а `install` и `status` выдают предупреждение — проверьте путь.

## Ограничения

- **Браузер покрыт только по диапазонам IP.** Хосты, которые Anthropic держит в
  чужих облаках (например, `downloads.claude.ai` в Google Cloud), из браузера
  доступны напрямую. Утверждение «Anthropic не видит реальный IP» верно для
  хостов внутри диапазонов из конфига. `status` предупреждает, когда имя из
  `checkDomains` резолвится за их пределы.
- **`claude.exe` заблокирован на всех интерфейсах, кроме VPN,** включая адреса
  локальной сети и Tailscale: локальные MCP-серверы на других машинах и загрузка
  с домашнего сервера не работают, если VPN не маршрутизирует эти адреса.
  Loopback разрешён.
- **Дочерние процессы `claude.exe`** (git, node, curl, MCP-серверы) правилом по
  приложению не покрыты — на них действует только правило по диапазонам IP.
- **Трафик WSL2 и виртуальных машин Hyper-V** не покрыт.
- **DNS-запросы** могут уходить мимо VPN.
- **Разрешающие фильтры постоянные и привязаны к LUID адаптера.** Пока служба не
  работает, они не обновляются: после переподключения VPN Claude может остаться
  заблокированным, пока служба не запустится снова.
- **Другой VPN-продукт,** чей sublayer имеет тот же максимальный вес и использует
  жёсткие разрешения (так делают некоторые kill switch и исключения
  split-tunnel), может перекрыть блокировку. На этой машине это пока не проверено.
