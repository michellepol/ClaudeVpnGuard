# ClaudeVpnGuard — дизайн

Дата: 2026-10-08

## Цель

Ни одно соединение с Anthropic с этой машины не должно уходить мимо AmneziaVPN.
Когда VPN выключен, отвалился или ещё не поднялся, Claude Code и сайты Claude
остаются без сети, а всё остальное работает как обычно.

Критерий успеха: Anthropic никогда не видит реальный IP машины — ни от
`claude.exe`, ни от браузера, ни от любой другой программы.

## Исходные факты (проверено 2026-10-08)

- Claude Code — нативный `C:\Users\ME\.local\bin\claude.exe`.
- Десктопное приложение Claude не установлено. Браузер по умолчанию — Helium (Chromium).
- AmneziaVPN работает по AmneziaWG и поднимает адаптер с именем `AmneziaVPN`
  (служба туннеля `AmneziaWGTunnel$AmneziaVPN`, запуск вручную — адаптер
  создаётся при подключении).
- Другие интерфейсы: `Ethernet 4` (физический), `Tailscale`, адаптеры Hyper-V.
- `api.anthropic.com`, `claude.ai`, `claude.com`, `platform.claude.com`,
  `console.anthropic.com`, `mcp-proxy.anthropic.com` резолвятся в `160.79.104.10`.
- Официальные диапазоны Anthropic
  (<https://platform.claude.com/docs/en/api/ip-addresses>):
  входящие `160.79.104.0/23` и `2607:6bc0::/48`, исходящие `160.79.104.0/21`.
  В конфиг по умолчанию идут `160.79.104.0/21` (надмножество) и `2607:6bc0::/48`.
- `downloads.claude.ai` живёт на Google Cloud (`35.190.46.17`), то есть вне
  диапазонов Anthropic. Поэтому кроме блокировки по IP нужна блокировка по exe.
- Установлен .NET SDK 9.0.316; других компиляторов нет.

## Правило

Разрешено только через адаптер `AmneziaVPN`, на остальных интерфейсах запрещено:

1. любые исходящие соединения к сетям Anthropic, от любого процесса;
2. любые исходящие соединения `claude.exe`, кроме loopback.

Tailscale за VPN не считается.

## Фильтры WFP

Собственные provider и sublayer с фиксированными GUID (константы в коде).
Provider, sublayer и все фильтры — постоянные (`PERSISTENT`), чтобы запрет
действовал до старта службы и после её падения.

Слои: `FWPM_LAYER_ALE_AUTH_CONNECT_V4` и `FWPM_LAYER_ALE_AUTH_CONNECT_V6`
(покрывают TCP и UDP, включая QUIC).

| Вес | Действие | Условия |
|---|---|---|
| 15 | permit | `IP_REMOTE_ADDRESS` в CIDR Anthropic **и** `IP_LOCAL_INTERFACE` = LUID адаптера |
| 15 | permit | `ALE_APP_ID` = приложение **и** `IP_LOCAL_INTERFACE` = LUID адаптера |
| 15 | permit | `ALE_APP_ID` = приложение **и** флаг `IS_LOOPBACK` |
| 1 | block | `IP_REMOTE_ADDRESS` в CIDR Anthropic |
| 1 | block | `ALE_APP_ID` = приложение |

- Фильтры по CIDR создаются отдельно на каждый диапазон: IPv4 — на слое V4,
  IPv6 — на слое V6. Фильтры по приложению создаются на обоих слоях для
  каждого пути из конфига.
- Если адаптера нет, ставятся только block-фильтры и permit для loopback.
- App ID получается через `FwpmGetAppIdFromFileName0`. Он привязан к пути,
  а не к содержимому, поэтому автообновление `claude.exe` его не ломает.
  Если файла по пути нет (автообновление переименованием, ошибка в пути),
  приложение всё равно блокируется: app ID вычисляется из пути в конфиге
  (NT-путь устройства через `QueryDosDevice`, буквы A–Z в нижнем регистре —
  тот же формат, что возвращает API), а `install`, служба и `status` выдают
  предупреждение. Путь должен начинаться с буквы локального диска.
- Блок в нашем sublayer не отменяется разрешениями брандмауэра Windows и
  других программ; наш permit не отменяет чужие блоки.

## Компоненты

Решение `ClaudeVpnGuard.sln`:

- `src/ClaudeVpnGuard` — консольное приложение `net9.0-windows`, публикуется
  одним self-contained exe под `win-x64`.
- `tests/ClaudeVpnGuard.Tests` — xUnit.

Модули:

| Модуль | Назначение | Зависит от |
|---|---|---|
| `Config` | Чтение и валидация `config.json`, значения по умолчанию | — |
| `Cidr` | Разбор CIDR в адрес и маску/префикс для IPv4 и IPv6 | — |
| `Policy` | Чистая функция: конфиг + LUID (или его отсутствие) + app ID → список описаний фильтров | `Config`, `Cidr` |
| `Wfp` | P/Invoke к `fwpuclnt.dll`: движок, транзакции, provider/sublayer, добавление, перечисление и удаление фильтров нашего provider | — |
| `Adapters` | Поиск LUID по имени адаптера, подписка на `NotifyIpInterfaceChange` | — |
| `Reconciler` | В одной транзакции удаляет все фильтры нашего provider и ставит набор из `Policy` | `Policy`, `Wfp`, `Adapters` |
| `GuardService` | `BackgroundService`: reconcile на старте и по событиям адаптеров (debounce 500 мс) | `Reconciler` |
| `Cli` | Команды `install`, `uninstall`, `status`, запуск в режиме службы | всё выше |

`Policy` возвращает обычные записи (слой, вес, действие, условия), не зная
о P/Invoke, — это единственное место с логикой правил, и оно тестируется без
прав администратора.

## Конфиг

`C:\Program Files\ClaudeVpnGuard\config.json`, создаётся при `install`,
если его ещё нет:

```json
{
  "adapterName": "AmneziaVPN",
  "ipv4Cidrs": ["160.79.104.0/21"],
  "ipv6Cidrs": ["2607:6bc0::/48"],
  "appPaths": ["C:\\Users\\ME\\.local\\bin\\claude.exe"],
  "checkDomains": [
    "api.anthropic.com", "claude.ai", "claude.com",
    "platform.claude.com", "console.anthropic.com", "mcp-proxy.anthropic.com"
  ]
}
```

Путь к `claude.exe` записывается абсолютным: служба работает от `LocalSystem`
и не знает профиля пользователя. Изменения конфига применяются перезапуском службы.

## CLI

- `ClaudeVpnGuard install` — копирует exe в `C:\Program Files\ClaudeVpnGuard`,
  создаёт конфиг, ставит фильтры, регистрирует службу `ClaudeVpnGuard`
  (`LocalSystem`, автозапуск, перезапуск при сбое) и запускает её.
  Повторный запуск безопасен: обновляет exe и фильтры.
- `ClaudeVpnGuard uninstall` — останавливает и удаляет службу, удаляет фильтры,
  sublayer и provider. Файлы и конфиг остаются.
- `ClaudeVpnGuard status` — показывает: состояние службы; число установленных
  фильтров; найден ли адаптер и совпадает ли его LUID с тем, что в permit-фильтрах;
  для каждого домена из `checkDomains` — попадают ли его адреса в диапазоны
  конфига (предупреждение, если нет). Код возврата 0 — всё в порядке, 2 — есть
  предупреждения.

`install` и `uninstall` без прав администратора завершаются с понятным
сообщением и кодом 1.

## Поведение при сбоях

| Ситуация | Результат |
|---|---|
| VPN выключен, адаптера нет | permit ни с чем не совпадает — Claude без сети |
| Amnezia пересоздала адаптер с новым LUID | Claude без сети, пока служба не обновит permit (доли секунды) |
| Служба упала или остановлена | фильтры остаются; при смене LUID Claude без сети до запуска службы |
| Перезагрузка | фильтры активны до старта службы |
| Ошибка WFP при reconcile | транзакция откатывается, старые фильтры остаются; ошибка в журнал событий Windows, повтор через 5 с |
| Некорректный конфиг | служба пишет ошибку в журнал и не трогает установленные фильтры |

Во всех случаях отказ ведёт к блокировке, а не к утечке.

## Проверка

Автоматически (без прав администратора):

- `Cidr`: IPv4 и IPv6, граничные префиксы, некорректный ввод.
- `Policy`: набор фильтров с адаптером и без; несколько CIDR и приложений;
  отсутствующий файл приложения — фильтры те же, что и для существующего,
  плюс предупреждение.
- `AppId`: вычисленный app ID побайтно равен результату
  `FwpmGetAppIdFromFileName0` для существующих файлов; для отсутствующего
  файла строится из пути.
- `Config`: значения по умолчанию, ошибки валидации.

Вручную после `install` (VPN включён):

1. `ClaudeVpnGuard status` — без предупреждений.
2. `curl --interface <IP Ethernet 4> https://api.anthropic.com` — не соединяется.
3. `curl https://api.anthropic.com` — соединяется (идёт через AmneziaVPN).
4. `curl --interface <IP Ethernet 4> https://example.com` — соединяется
   (посторонний трафик не задет).
5. Claude Code продолжает работать.

Вручную, делает пользователь в самом конце (оборвёт сессию Claude Code):

6. Отключить AmneziaVPN — Claude Code и `claude.ai` в браузере без сети,
   остальные сайты открываются.
7. Включить AmneziaVPN — Claude снова работает без перезапуска службы.
8. `ClaudeVpnGuard uninstall` — всё работает как до установки.

## Ограничения

- Браузер покрыт только по IP. Если Anthropic вынесет `claude.ai` на CDN или
  добавит диапазоны, появится дыра; её обнаруживает `status`.
- DNS-запрос имени может уйти мимо VPN: провайдер видит имя, Anthropic
  реальный IP не видит.
- Блокировка действует на всю машину, включая другие учётные записи.
- Трафик WSL2 и виртуальных машин Hyper-V идёт через слой форвардинга, а не
  через `ALE_AUTH_CONNECT`, и этими фильтрами не покрывается.

## Вне рамок

- Дочерние процессы `claude.exe` (git, node, curl, MCP-серверы).
- Входящие соединения.
- Блокировка по доменным именам и защита от утечек DNS.
- Иконка в трее, GUI, автообновление диапазонов.
- Трафик WSL2 и виртуальных машин.
